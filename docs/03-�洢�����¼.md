# 存储子系统调查记录（SDHCI / eMMC / microSD）

> 时间跨度：2026-11-04 → 2026-11-17
> 结果：**控制器全部驱动成功，eMMC 卡识别成功；数据读写未打通，microSD 受限于供电。**
> 本文按时间顺序记录每一轮实验的**观测数据**，包括所有失败路径。
> 目的是让接手的人不必重走同样的弯路。

## 1. 起点：把控制器登记成「非可发现设备」

思路：复用 EDK2 现成的分层结构，只写「把控制器登记出来」这一步：

```
SdhcPlatformDxe            → 注册 0x07824900 为 Non-Discoverable SDHCI
NonDiscoverablePciDeviceDxe → 包装成 EFI_PCI_IO_PROTOCOL
SdMmcPciHcDxe              → 通用 SDHCI 驱动 → SdMmcPassThru
EmmcDxe / SdDxe            → 卡识别 → EFI_BLOCK_IO_PROTOCOL
```

第一次结果：`map -r` 只有两个 `MemoryMapped` 卷，没有任何块设备。

---

## 2. 诊断基础设施：scratch 内存区

没有 UART，所以把寄存器快照写进一块固定内存，再由 shell 的 `dmem` 打印。

```c
#define SDHCI_SCRATCH_PA  0x9F310000ULL
ScratchWrite (index, value);   // MmioWrite32(PA + index*4, value)
```

**踩过的坑**：这块内存后来被别的组件分配走了（`0x9F310070` 变成了 ASCII
`"ligned.c"`）。修复办法是在驱动入口先 `gBS->AllocatePages(AllocateAddress, ...)`
把这一页占住。**接手者如果沿用这个机制，务必保留这一步。**

## 3. 崩溃一：非对齐访问

```
Synchronous Exception at 0x0000FC6104E8  (SdhcPlatformDxe+0x14E8)
X0  = 0x0000000078649FE     FAR = 0x0000000078649FE
ESR: EC 0x25 ISS 0x10       Data abort: Alignment fault
```

原因：`0x7824900 + 0xFE` 是 SDHCI **VERSION** 寄存器，16 位，用 `MmioRead32` 读触发
对齐异常。**SDHCI 的 VERSION(0xFE)、CLOCK_CONTROL(0x2C)、HOST_CTRL1(0x28) 都是
8/16 位寄存器**，必须用对应宽度访问；尤其 `HOST_CTRL1`(0x28) 后面紧跟
`POWER_CONTROL`(0x29)，用 16 位写会连电源设置一起改掉。

---

## 4. 卡住：HC 模式与软复位

修好宽度后读到的快照：

| 寄存器 | 值 | 结论 |
|---|---|---|
| VERSION (0xFE) | `0x4D02` | 控制器活着（SDHCI 3.00） |
| CAPABILITIES (0x40) | `0x342DC8B2` | 基频 200 MHz |
| PRESENT_STATE (0x24) | `0x01F80000` | 空闲；**bit16=0（Card Inserted 未置位）** |
| CLOCK_CONTROL (0x2C) | `0x0007` | 时钟已使能且稳定 |
| HC_MODE (core+0x78) | `0x00000000` | **未进入 SDHCI 模式** |
| 软复位轮询 | 1000 次用满，读回 `0x01` | **复位永远不完成** |

结论：没有 HC 模式，软复位不会完成。

## 5. 关键 bug：lk2nd 宏的参数顺序

lk2nd 的 `sdhci_msm.c:sdhci_msm_init()`：

```c
REG_WRITE32(host, 0xA1C, SDCC_VENDOR_SPECIFIC_FUNC);
RMWREG32(pwrctl_base + SDCC_MCI_HC_MODE, bit 0,  1, 1);
RMWREG32(pwrctl_base + SDCC_MCI_HC_MODE, bit 13, 1, 1);
sdhci_reset(host, SDHCI_SOFT_RESET);
```

而宏定义是：

```c
#define REG_WRITE32(host, v, a)  writel(v, (host->base + a))     // 值在前，寄存器在后
```

所以真实含义是 **把 `0xA1C` 写进偏移 `0x10C`**。我一开始写反了（把 `0x10C` 写进
`0xA1C`），白白多花两轮。修正后：

| 寄存器 | 修正后 |
|---|---|
| `*(0x7824900 + 0x10C)` | `0x00000A1C` ✓ |
| 软复位轮询 | **0 次**（第一次读就已清除）✓ |
| HC_MODE | bit0=1 ✓ |

**教训：跨项目抄寄存器序列时，先确认宏的参数顺序。**

## 6. 卡能识别，但 EmmCxe 不认领

`dh -p 716ef0d9-…`（SdMmcPassThru）显示 handle 29 存在，
`dh -p 964e5b21-…`（BlockIo）**一条都没有**。

写了 `MmcProbe.efi` 直接通过 `SdMmcPassThru` 发命令，第一次的结果：

```
ResetDevice -> No Media
CMD0/CMD1/CMD2/CMD13 -> 全部 No Media
```

`No Media` 来自 `SdMmcPciHcPassThru` 的第一句
`if (!Private->Slot[Slot].MediaPresent) return EFI_NO_MEDIA;`。

`MediaPresent` 由 `SdMmcHcCardDetect()` 依据 `PRESENT_STATE` bit16 决定。
**eMMC 焊死、没有卡检测引脚，该位恒 0。** 补丁（`build-mido-all.sh` 第 2 段）：

```c
// SdMmcPciHci.c, SdMmcHcCardDetect()
*MediaPresent = TRUE;
```

之后命令终于发得出去，eMMC 立刻回应：`CMD0 → Success`、`CMD1 → OCR=0xC0FF8080`、
`CMD2 → CID=0x8BD34B244D42072A5258314200150100`。

## 7. 弯路：SlotType / EmbeddedSlot

曾怀疑 `EmmcDxe` 因设备路径分类拒绑：

```c
if (DevicePath->SubType != MSG_EMMC_DP) return EFI_UNSUPPORTED;
```

`SlotType` 来自 CAPABILITIES bits30:31，本机读作 `00` = Removable。
把 `Private->Slot[Slot].SlotType` 强制改成 `EmbeddedSlot` —— **无效**，且会影响
SD 槽，后来撤销。

## 8. 弯路：eMMC 的 RCA 语义（最重要的一条）

错误做法：CMD3 用 **R6**、参数 `0x00010000`、并采信卡返回的 RCA。结果：

```
CMD3 -> Success  raw=0x00400500   (=RCA 0x40, status 0x500, 状态=2 ident)
CMD9 (rca=0x40) -> Device Error
CMD7 (rca=0x40) -> Device Error
CMD13 (arg 0)   -> Success status=0x00000700   ← 状态 3 Tran（假象）
```

卡一直停在 ident 状态，CMD7 永远选不中。

**正解来自 lk2nd** `platform/msm_shared/mmc.c:820`：

```c
if (card->type == SDHC || card->type == STD_SD) {
    cmd.argument = 0;                       // SD：卡自己决定 RCA
    card->rca = (cmd.resp[0] >> 16);
} else {                                    // MMC / eMMC
    cmd.argument  = (MMC_RCA << 16);        // MMC_RCA = 2，主机指定
    cmd.resp_type = MMC_BOOT_RESP_R1;       // ← R1，不是 R6
}
```

照抄后：

```
CMD3 (Ac, R1, arg 0x00020000) -> Success  rca=0x0002  status=0x00400500
CMD9 (Ac, R2, arg 0x00020000) -> Success  csd=0xEF8E4040FF6DBFF
CMD7 (Ac, R1, arg 0x00020000) -> Success          ← 选中成功
CMD13 (Ac, R1, arg 0x00020000) -> Success status=0x00000900   ← 状态 4 Tran ✓
CMD16 (Ac, R1, arg 512)        -> Success
CMD17 (Adtc, R1, arg 0)        -> Time out        ← 只剩数据通路
```

## 9. 弯路：SDCC2 一碰就崩

第一次访问 SDCC2（microSD）就崩溃：

```
ESR: EC 0x25 ISS 0x10   Data abort: Synchronous external abort
FAR = 0x078649FE        (SDCC2_SDHCI_BASE + VERSION)
```

**根因：lk2nd 从不初始化 SDCC2**（它只从 eMMC 的 boot 分区读内核，SD 卡由 Linux
内核自己接管），所以 GCC 里 SDCC2 的分支时钟是关的。

**判据（务必记住）**：
- `Synchronous external abort` + 合理地址 ⇒ **外设时钟没开**
- `Translation fault` ⇒ 地址没映射

## 10. SDCC2 时钟树（已验证可用）

从 lk2nd `platform/msm8953/msm8953-clock.c` 的 `F(50000000, gpll0, 16, 0, 0)` 推算，
用 `clock_lib2.h` 的位域编码：

```c
MmioWrite32(0x01843000, 0);            // BCR 解除复位
MmioWrite32(0x0184300C, 0);            // M
MmioWrite32(0x01843010, 0);            // N
MmioWrite32(0x01843014, 0xFFFFFFFF);   // D（n=0 时 LK 就是这么写的）
cfg  = MmioRead32(0x01843008);         // CFG_RCGR
cfg &= ~((0x7<<8) | 0x1F | (0x3<<12));
cfg |= (1<<8) | 0x1F;                  // src=GPLL0, div=16 → 50 MHz
MmioWrite32(0x01843008, cfg);
MmioOr32(0x01843004, 1);               // CMD_RCGR 触发更新
while (MmioRead32(0x01843004) & 1) ;
MmioOr32(0x0184301C, 1);               // AHB_CBCR，等 bit31=0
MmioOr32(0x01843018, 1);               // APPS_CBCR，等 bit31=0
```

实测验证：

| 检查 | 结果 |
|---|---|
| `CFG_RCGR` 读回 | `0x0000011F` ✓（正是写入值） |
| 时钟稳定位轮询次数 | **0**（第一次读就已稳定）✓ |
| `CLOCK_CONTROL` | `0x0003` ✓ |
| VERSION | `0x4D02` ✓（与 SDCC1 相同） |
| CAPABILITIES | `0x302DC8B2`（与 SDCC1 只差 bit26 = DDR50） |

**通用流程**：`BCR 解除 → RCG 配置 → CMD 更新并等待 → CBCR 使能并等 bit31 清零`。

## 11. SDCC2：控制器正常，但卡没电

用 scratch 标记证实 `SdMmcHcInitHost` 内部两步都成功：

| 标记 | 值 | 含义 |
|---|---|---|
| w32 | `0x04000000` | `SdMmcHcInitV4Enhancements` 成功 |
| w33 | `0x05000000` | `SdMmcHcClockSupply(400 kHz)` 成功 |
| w34 | `2` | 控制器版本 2（SDHCI 3.0） |
| w35 | `0xC8` = 200 | 基频 200 MHz |

但所有命令超时。查 DTB（`dumps/mido-live.dts` 的 `sdhci@7864900` 节点）：

```
vdd-supply    = <0x131>   qcom,vdd-voltage-level    = <0x2d0370>   (2.95 V)
vdd-io-supply = <0x132>   qcom,vdd-io-voltage-level = <0x1b7740>
```

这两个是 **`qcom,rpm-smd-regulator`** —— 由 RPM（独立小核上的电源管理器）经 SMD/SPMI
控制。**UEFI 没有 RPM 驱动，所以 SD 卡在 UEFI 下没有电。**

要让 microSD 工作，必须先实现：SMEM 通信 + APCS IPC 中断 + RPM 资源请求（SMD）。

## 12. eMMC 数据通路：试过且无效的方案

| 实验 | 做法 | 结果 |
|---|---|---|
| 先在选中状态直接读 | 不复位，直接 CMD16+CMD17 | CMD16 Success、CMD17 Time out |
| 主机复位后再读 | `ResetDevice`（400 kHz/1-bit）后 CMD16+CMD17 | CMD16 Success、CMD17 Time out |
| 总线位宽 | 读 `HOST_CTRL1`(0x28) = `0x39`；bit1=0 本来就是 1 位 | 不是原因 |
| DMA 选择位 | bits4:3 从 `11`(64-bit ADMA2) 改成 `10`(32-bit) | 无效（驱动每次传送会重写） |
| 缓存一致性 | 注册为 `DmaTypeNonCoherent` | **全部命令都失败**，已回退 |
| 强制 PIO | 清 `Adma2` + `Sdma` | **全部命令都失败**，已回退 |
| 改用 SDMA | 只清 `Adma2`（保留 `Sdma`） | 仍 Time out |

`HOST_CTRL1 = 0x39` 解读：LED=1、**1-bit**、DMA 选择=`11`、1.8V 信号；
相邻的 `POWER_CONTROL = 0x0B`：供电开、VDD1=1.8V。

**剩下的三个方向**：
1. **描述符内存的 cache 维护**：EDK2 在 Coherent 下不做 flush，而 msm8953 的 SDCC
   不是 cache-coherent。需要在描述符写入后手工 `WriteBackDataCacheRange`。
2. **1.8V 时序**：卡在 HS400 之后 IO 电压是 1.8V，400 kHz 下 1.8V 采样的稳定性值得验证。
3. **自己写块设备驱动**（推荐）：照 lk2nd 的 `mmc.c`/`sdhci.c`，直接用寄存器 +
   手工 cache 维护，不经过 EDK2 的 DMA 抽象层。

## 13. 复用建议

如果接手者只想尽快看到「块设备」，建议路径：

1. 保留 `SdhcPlatformDxe`（HC 模式 + 时钟 + 复位，已验证可用）
2. **不要**依赖 `SdMmcPassThru` 做数据传送
3. 在 `SdhcPlatformDxe` 里自己实现：
   - 命令发送：写 `CMD`/`ARG`/`TRANSFER_MODE` 寄存器，轮询 `NORMAL_INT_STATUS`
   - 数据读：先写 `BLOCK_SIZE`/`BLOCK_COUNT`/`SDMA_ADDR`，用 **SDMA** 单缓冲
     （避免描述符表），缓冲区必须用 `AllocatePages` + 手工 cache 维护
   - 产出 `EFI_BLOCK_IO_PROTOCOL`（512 字节块）
4. 卡初始化严格照本文 §8 的序列（**RCA=2、CMD3 用 R1**）

这样可以把「EDK2 抽象层的未知行为」完全排除在外。
